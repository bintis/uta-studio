# Uta! Studio：MIDI／目标音符碎片化诊断与模型、算法改进报告

报告日期：2026-09-11（Asia/Tokyo）

范围：源码审计、既有全曲 JSON 产物统计、公开模型一手资料核查；本次交付为报告，不是已实施的修复。

## 1. 结论与优先级

**有办法改善。对本项目，优先级最高的不是再堆一个转 MIDI 模型，而是修正“长音频歌词对齐 → 音符候选生成 → 结构化解码 → 最终谱面投影”这条链。** 目前已有 GAME、RMVPE、F0 合并候选和 HSMM；继续增加模型或只把最短音符限制调大，都可能掩盖真正的问题。

本次最值得先处理的三件事是：

1. **长音频对齐不能按歌词字符数在整首歌上比例分窗。** 当前实现确实这样分配，并把部分异常词区间修成 1 毫秒。已有样例的 628 个对齐词元中，362 个时长恰为 1 毫秒。应先保留 ASR 音频片段锚点，再做局部精对齐，避免错误歌词边界继续影响音符。
2. **让长音候选真正进入现有 HSMM。** 当前 F0 consolidation 需要相邻片段严格首尾相接，且歌词边界、Basic Pitch onset、声学瞬态等均可否决合并。已有样例的 21,875 个候选中没有记录到 F0 consolidation 类型。候选池没有合理长音时，算法或 AI 选择器都选不出来。
3. **分离 F0 保留与音符整形，并让最终谱面投影不再偷偷改音符语义。** 现在 `preserve_continuous_pitch` 同时影响 PitchEvidence 和同词内音符合并；合并又只看相同 MIDI 音高及不超过 20 毫秒的间隔，不检查重新起音，既可能漏合并，也可能误合并。

**近期推荐路线：保留 GAME medium＋RMVPE，修复对齐调度和候选／HSMM，ROSVOT 作为边界挑战者；中期评估独立词边界预测 RWBD 和 STARS 的唱歌对齐能力；VocalParse 作为中文短片段的研究候选，而非当前日语全曲流程的直接替代。** 外部模型依据见第 6、10 节。

这些优先级来自源码与已有产物的联合分析，不代表已经证明用户遇到的每一个碎音都由同一原因造成。

## 4. 根因分析：哪些已经确认，哪些还需实验

### 4.1 最高优先级：长音频对齐的窗口分配依据不可靠

位置：`native-inference/ggml-runtime/src/qwen/aligner.rs:48–138,258–321`。

`align_long_words` 调用 `assign_words_to_windows`；后者以非空白字符数为权重，把文本累计位置映射到整段音频样本位置，再决定每个词进入哪个固定音频窗口。这个步骤不使用真实的演唱起点、前奏／间奏长度或词在 ASR 音频块中的锚点。

对包含长前奏、间奏、重复副歌、拖腔和快慢句变化的歌曲，这种先验容易把正确的词交给错误的音频窗口。即使局部强制对齐器本身很好，也无法在一个不包含该词的窗口内找到正确发音。这是结构性风险，不是“模型再大一点”就能保证解决的问题。

同文件 `repair_word_ranges` 使用毫秒单位，将结束时间至少设为 `start + 1`，同时确保词元单调不重叠。这样的修补能得到合法区间，却不能恢复声学对齐；连续退化区间可能表现为一串 1 毫秒词元。已有产物的大量 1 毫秒词元与该机制相符，但尚需比较 raw／corrected 时间戳才能逐个确认来源。

影响链条可能是：错误分窗 → 局部对齐坍缩 → 密集短词边界 → 长音候选受阻或歌词归属失真 → spoken 占位或多个歌词挤入短音。最后两步还需要逐阶段回放验证，不能把相关性写成已经完成的因果证明。

### 4.2 合理长音候选可能在进入 HSMM 之前就被否决

位置：`analysis-engine/src/fusion/candidate_states.rs:178–332,338–431`。

代码已经实现 F0 consolidation，不应重复提议“从零添加长音合并”。当前限制包括：相邻边界严格满足 `previous.end == next.start`；词边界附近否决；Basic Pitch onset 和声学 flux 瞬态附近否决；调用方边界及持久音高变化附近否决；整段还要求 F0 稳定和足够的可信帧。

这是保守且有意保护重新起音的设计，但也可能使错误歌词边界、轻微帧间隙、辅音瞬态或低置信 F0 阻止合理的持续音候选。整段候选复核失败后直接跳过，还应检查是否遗漏可用的较短子区间。

应保留用户明确的硬边界。需要改的是**自动词边界与普通瞬态的证据权重和独立性**，不是把所有边界全部软化。密集预测词边界不能天然等同于用户权威的分音指令。

### 4.3 HSMM 已经惩罚碎片，但不能弥补候选缺失

位置：`analysis-engine/src/fusion/hsmm.rs:503–561,751–852,935–999`。

当前 emission 已有每个状态的固定复杂度成本、短音项、起音证据和音高一致性项，也有转移及短八度往返处理。建议是改进现有结构化解码，而非再套一个名字不同的 HMM。

有两项值得单独消融：首先，长音候选是否存在；其次，强起音奖励、固定状态成本、短音惩罚及转移项是否校准。源码中的 onset 奖励最高为 0.7，而固定状态成本为 0.45；这不证明最终路径一定偏向碎片，但说明如果伪瞬态被当作强起音，单靠固定成本未必足够。最终效果还受其他特征和转移影响。

`validate_candidate_path` 要求覆盖候选表示的 voiced 连通区域。这是现有覆盖语义，不应为了“音符更少”删除真实覆盖。反过来，上游错误 voiced 区域也需要可解释的无声／不确定证据，而不能逼解码器总在坏候选中选一个。

### 4.4 最终合并同时存在漏合并和误合并风险

位置：`analysis-engine/src/artifact/vocal_chart.rs:35–66,162–207,250–294`。

最终器按 `word_id` 归组，仅在同一词组内、同 MIDI 整数音高、间隔不超过 20 毫秒时合并。跨词的连续音、微小半音跳动和稍大于 20 毫秒的间隙仍会保留碎片。

另一方面，该合并函数没有使用重新起音、呼吸、硬边界或原始 F0 连续性证据。两个真实的同音反复也可能被合成一个。不同词应不应该连成一个音，取决于音频中的重新发音和产品的记谱目标，不能仅按词 ID 决定。

`workflow_execution.rs:148–154` 表明 finalizer 可能接收已经量化过的 candidate track。因此，该位置的语义合并还可能改变上游已选择的边界。推荐把音乐意义上的整形放回可审计的候选／解码层；最终器主要负责投影、歌词关联和格式约束。

### 4.5 开关耦合，以及无音高占位不能假装识别成功

位置：`desktop/src/studio/settings/analysis.rs:55`、`app-core/src/analysis_engine_adapter.rs:605–607,683–684`、`analysis-engine/src/artifact/vocal_chart.rs:71–117,210–294`。

界面对 `preserve_continuous_pitch` 的说明是保留独立 F0 PitchEvidence；适配层确实用它控制 pitch evidence，同时 finalizer 又用它决定音符合并。用户因此无法独立表达“保留原始音高曲线，但不改动重新起音结构”。

没有候选音符的词可能被投影为无音高 spoken／rhythm 占位，被有音高音符完全占据的词还可能补挂到其他音符。这可以维持文字覆盖，但**没有音高证据不等于已经识别为真实说话声**。应把未对齐／待确认与真实 spoken 语义区分，防止 UI、统计或导出误读。

此外，最终器首先按 `word_id` 收集音符。无歌词归属的旋律候选可能不进入这个歌词驱动的谱面视图。这可能是当前产品策略而非错误，但纯旋律 MIDI 输出必须明确是否保留哼唱、漏识别歌词的旋律和无词拖音，不能让歌词缺失悄悄变成旋律丢失。

### 4.6 其他真实风险，但本次不能归因为已证实缺陷

分离不确定、和声泄漏、八度错误、F0 低置信、模型分块接缝和原生移植数值误差都可能影响音符。项目已经存在 GAME、ROSVOT、STARS 的分块拼接实现，不能声称“完全没有接缝处理”。应检查实际接缝位置与碎音的对应关系，并做窗口偏移不变性测试。

同样，模型成功执行或单个参考片段通过，不代表原生移植在所有歌声上已与上游一致。应优先补齐现有模型的参考比较，而非把尚未排除的移植问题归咎于模型能力。

## 5. 建议的算法与工程修复

### 5.1 先修对齐：分层锚定，而不是整首按文字长度均摊

建议保留 ASR 每个音频块的绝对时间范围和对应文本词元身份。先在这些真实音频范围内建立句／短语级锚点，再进行词或音素级精对齐；较长的无主唱区间允许被跳过，重叠块通过单调文本／声学匹配去重。

用户提供完整歌词时，可采用“粗粒度歌词与 ASR 片段匹配 → 有限带宽的单调动态规划 → 短片段强制对齐”。重复歌词需要同时利用顺序与声学锚点，不能只做字符串首次匹配。没有可靠锚点的区域保留为未确定，而不是强行均匀摊开。

原始、修正后的时间戳及修补原因应保留。1 毫秒修补区间不再作为可靠的切音硬依据，而是在 review region 和 UI 中明确标出。这里是质量与证据分级，不增加禁止用户编辑或导出的新限制，也不引入静默模型回退。

### 5.2 候选生成：同时提出“持续音”和“重新起音”解释

在同一声部内，对相邻的细粒度边界同时保留原分段与有证据支持的较粗分段。允许有界的小间隙桥接，但必须结合前后可信 F0、能量和有无重新起音证据；不得跨过真实呼吸、静音、声部切换或用户硬边界。

自动词边界是辅助信息，不是默认否决。Basic Pitch onset、声学 flux 和辅音爆破也不能自动等价为音乐起音；应检验起音前后的能量包络、声带周期性恢复及局部音高变化。共享 RMVPE 或相同上游对齐的专家需要相关性折扣，不能把共同错误当作多票独立支持。

当最长候选整体失败时，产生有依据的子区间候选，而非仅保留碎片。候选数量需有界，使用局部时间索引和既有资源预算，避免枚举整首所有区间造成平方级膨胀。

新增诊断应记录：每种粗候选生成数量、否决原因计数、被选比例、与用户硬边界的关系、保留和合并的源 ID。先解释“为什么没有候选”，再决定阈值。

### 5.3 用现有 HSMM 做音乐事件解码，而不是逐帧量化

建议的状态语义是：起音、持续、同音重新起音、释放／无声；目标音高中心与连续表现音高分离。代价函数可继续建立在现有 emission／transition 上，加入经标注数据校准的时长先验与边界可靠性：

```text
路径代价 = 音高解释误差 + 起音/释放不一致代价
         + 音符复杂度 + 条件时长先验
         + 软歌词约束 + 跳音/往返代价
```

这是一项设计建议，不是已经训练或验证的概率模型。未校准分数不能宣称为跨模型可比较的概率。

时长先验应与演唱速度、局部节拍和音符类型有关；节拍不可靠时降低其权重，不要强制贴网格。50–100 毫秒可以是真实倚音、快速音或辅音前后的短音。不得以“小于 100 毫秒就删除”作为修复。

音高方面保留 `69 + 12*log2(f/440)` 的连续半音值，在候选区间内估计稳健中心，并对换音使用迟滞和最短持续证据。颤音和滑音留在 PitchEvidence／表现层，不因为来回跨越半音取整边界就产生一串 NoteOn。当前 `fusion/baseline.rs:65–79` 已采用片段级音高决策，不能误写成现有实现是逐帧四舍五入；重点是补齐跨候选的一致性和音符中心稳定性。

### 5.4 分离三层数据和两个设置

建议明确区分：**连续表现证据**（F0、置信度、颤音／滑音）、**声学音符事件**（真实起音、持续、释放）、**目标谱面**（适于演唱、编辑和导出的离散音符及歌词关系）。目标谱面不等于每一次声学波动的逐字照抄，也不能为了整齐而编造与音频不符的旋律。

`preserve_continuous_pitch` 只负责是否保留连续证据；音符整形用独立且语义清楚的策略参数。不要设置一个模糊的“AI 修复力度”同时改变多种机制。参数变化进入既有执行 fingerprint，按当前协议原位演进，不新增兼容分支或平行版本协议。

一个词可以拖过多个音，一个音也可能关联多个歌词词元；两者用映射表示，而非互相强制切碎。无可靠音高的歌词应能标为未确定。无歌词旋律是否进入产品谱面和纯旋律导出，需要明确且可见的策略。

finalizer 保持可追踪的投影；若确需末端整形，也必须使用与上游一致的证据和硬边界，记录合并前后 ID／区间，不再只保留第一个 ID 就丢失整形来历。

### 5.5 对已经生成的谱面，提供保守的局部修复通道

使用保存的 F0、onset、词时间及 review region 对可疑区域重新解码，可复用已完成的模型证据，不必每次重跑全曲分离和 ASR。修改输出为新的 Candidate 或局部建议，不覆盖 Authored。

对于只有 `.mid`、没有原音频和证据的情况，只能做保守的同音短间隙建议、事件结构检查和人工确认，无法可靠区分颤音误切与真实同音反复。不要自动把相邻半音改成同一个音，也不要自动删掉短音。此报告不声称已对用户文件执行这些修复。

### 5.6 MIDI 真正写出端的核查清单

拿到实际导出器后，应比较“最终有音高事件 → 写出事件 → 读回事件”三个阶段。SMF 是带时间的事件交换格式，不能只看文件能否打开。[W9]

实现检查应覆盖：tempo map 下由绝对时间转换 tick，再形成事件 delta；同 tick、同声部同音高的结束／重新开始顺序；NoteOn／NoteOff 配对；量化后正时长；跨轨、跨 channel 的音符不误配；pitch bend 状态不污染下一音；无音高占位不被默认为 C4 等任意音高；歌词作为关联文字而不是额外 NoteOn。

恒定 tempo 的 PPQN 模式下可用 `tick = seconds × PPQN × 1,000,000 / tempo_us_per_quarter` 检查转换；变速时应分段积分，而不是每段 delta 都套最后一次 tempo。为防累计舍入误差，宜从绝对时间求各端点。上述是待实施的检查方案，不是已定位到当前导出器的错误。[W10]

如果 Candidate 已碎，应回到对齐／解码；如果 Candidate 正常而读回 MIDI 才碎，再修序列化或外部转换器。所有格式应消费同一套经确认的音符语义，不应在每个导出器里各写一遍不同的“去碎片”算法。

## 6. 更好的模型：按项目目标而不是按新旧选型

| 模型／路线 | 对本项目的适用点 | 局限与建议 |
| --- | --- | --- |
| **GAME medium＋RMVPE＋改进现有 HSMM** | 已有原生链路；GAME 针对歌声记谱，RMVPE 提供人声音高证据。[W1][W2] | **近期首选。** 先修窗口、边界和解码，再在同一歌曲集比较 GAME medium／large；不能假定 large 必然更准确。 |
| **ROSVOT＋独立词边界 RWBD** | ROSVOT 上游提供无手工词时长时的 RWBD 路径，可评估是否减少对坏对齐的依赖。[W3] | 项目已有 ROSVOT 不代表已接入 RWBD。现有 conditioned 专家共享对齐和 RMVPE，不是完全独立的投票。上游发布权重仅用 M4Singer 训练，日语适用性需实测。 |
| **STARS** | 联合唱歌转写、音素／词对齐和唱法标注，适合比单纯 MIDI 更完整的标注目标。[W4][W5] | 上游提供中文及中英权重，并要求匹配的音素集。不能直接宣称日语优于 GAME。应补齐项目原生输出对比，再按语言评估其对齐能力。 |
| **VocalParse-1.7B** | 2026 年发布，基于 Qwen3-ASR，把歌词、音高、音符时值与 BPM 联合生成；适合评估减少文字／音符级联错误的潜力。[W6][W7] | **研究候选，不立即替换。** 官方模型卡说明主要普通话训练、不预测真实音符时长、超过 30 秒应预切分。[W7] 仍需音频时间锚定、native 移植和目标语言验证。 |
| **Basic Pitch** | 通用、轻量、多音高音符转写，可提供 onset／activation 对照。[W8] | 不把它作为主唱语义的最高权威。建议保留辅助证据，但降低未经校准瞬态对持续音候选的否决权。 |
| **FCPE／JBM555 等项目现有挑战者** | 能做已有 F0／音符提案的差异诊断。项目角色见 `docs/AUDIO_MODELS.md`。 | 先做去掉／加入该专家的消融；候选更多不等于效果更好，也不能因个别参考测试成功就宣布质量领先。 |

### 6.1 为什么不建议立即换掉 GAME

GAME 的上游定位已经是歌声转谱，并支持已知边界条件、可调边界／存在阈值和浮点音高。[W1] 本项目的问题与“边界的来源与使用方式”高度相关。未经验证地从 GAME 换到另一套音符模型，仍然接收同一组错误歌词边界，可能保留同一问题。

推荐把每个模型当作证据提供者，比较实际歌曲上的音符起止、音高、歌词关系和人工修谱成本。不要把跨论文、跨数据集的指标拼成一个虚假的模型总排名。

### 6.2 VocalParse 的正确定位

它与本项目已经使用的 Qwen3-ASR 同族，可能有前端／运行时复用机会；但新增词表、权重、结构化生成和后处理仍需逐项核查，不能视为直接换一个 GGUF 即可上线。[W6][W7]

本项目要求可靠的实际起止时间；该公开 checkpoint 的音符时值与全局 BPM 不能直接替代逐音符的真实 onset／offset。日语支持也不能从基础 ASR 的语言能力自动推导到其唱歌微调 checkpoint。[W7]

因此适合先在中文短乐句上离线比较，把输出重新锚定到音频，并作为 Engine 的有来源候选，而不是让语言模型在 Stage 4 凭空生成最终音符。当前“只能从真实候选中选择”的约束应保留；缺失长音候选必须在候选生成层解决。

### 6.3 长期更值得投入的模型方向

若已有模型与解码修复后仍不足，可用项目真实错误片段训练一个较小的**边界／音符状态模型**：输入声学特征、F0、voicing 与 onset 证据，区分起音、持续、同音重起、释放，并预测稳定音高中心。对颤音、辅音、分离伪影和漏词进行针对性训练，通常比仅追求更大的通用转写模型更贴合本任务；这里是研发方向判断，尚无本项目实验结果支持收益幅度。

训练标签必须包含同音反复、长拖音、短倚音、间奏和不确定区域。以质量明确的人工校正数据为核心，不把当前碎片化输出直接当作真值。生产部署仍按项目原生 Runtime 实现，参考研究环境不成为应用自动 fallback。

## 8. 验收：既要少碎，也不能把真的音吃掉

### 8.1 评测材料

建议先建立约 30–60 个可复听的短片段，覆盖项目目标语言、长音／颤音、同音反复、快速短音、滑音、低音／高音、漏词、辅音、间奏、和声泄漏和每种模型的分块接缝，再补完整歌曲。训练、调参和最终评测按歌曲／歌手隔离。

音符真值应明确“可演唱目标音符”与“逐细节表现音高”的区别。两名标注者复核争议片段；含糊边界标为不确定而非强行制造唯一真值。只看原始 F0 平均误差不足以评价 MIDI 是否好用。

### 8.2 指标

标准音符指标建议同时报告 onset＋pitch F1 和 onset＋offset＋pitch F1。可采用 mir_eval 默认匹配容差：起音 50 毫秒、音高 50 cents，结束容差为 50 毫秒与参考时长 20% 中较大者；这些是评测匹配容差，**不是合并阈值或最短音长**。[W11]

另外报告项目指标：

| 指标 | 建议定义／用途 |
| --- | --- |
| 碎片率 | 在人工确认的单个参考音内，统计同声部、音高相符且具有显著重叠的连续预测音符链；当链含多个无参考重起音的片段时记为碎片。重叠、间隙阈值在调参集确定并随结果公开。不能把一次偶然擦边重叠算作碎片。 |
| 过度合并率 | 一个预测音覆盖多个参考起音／音符的比例，尤其单列同音反复。 |
| 真短音召回率 | 对人工标注短于 100 毫秒的音符单独评价，防止“删除短音”刷好看指标。 |
| 无声误报与覆盖 | 在真实静音／间奏中的有音高事件、真实人声覆盖缺失分别统计。 |
| 对齐退化 | 修补词元比例、1 毫秒词元比例、词被挤到窗口边缘比例及原始／修正时间偏移。1 毫秒比例是预警，不是独立质量真值。 |
| 歌词关系 | 未对齐词、无歌词旋律、多个词集中到极短音的区域，以及一词多音关系是否保留。 |
| 可编辑性 | 人工拆分／合并／移音操作数与每分钟音频的修谱时间，辅以盲听比较。 |
| 工程代价 | 同设备、同后端、同精度和相同日志条件下的运行时间、显存、候选规模与失败／退化情况。 |

建议比较当前实现、仅修对齐、仅改粗候选、两者结合、再调 HSMM、最后替换／增加模型。先用保存证据做算法消融，再在受控条件下重新跑模型。不能把“执行成功”当作上述质量指标通过。

可讨论的产品目标是：人工确认的误碎片数明显下降，同时标准 F1、真实短音召回和同音反复保持不退化；人工修谱操作同步减少。具体百分比要由带真值的首轮测量决定，本文不虚构“提升 30%”之类结果，也不设未经授权的新冻结基线或运行限制。

### 8.3 必须覆盖的回归情形

至少覆盖同音连续但无新起音、同音连续且有新起音、词变而声学持续、一词多音、68.49／68.51 半音附近的抖动、持续真实半音变化、短呼吸、真实倚音、F0 缺帧、八度短往返、对齐 1 毫秒串、用户硬边界、跨块时间偏移、无词哼唱以及无音高歌词导出。

其中“词变而声学持续”的预期必须由谱面语义决定，不能默认全合并；“无新起音”也需要音频证据，不得以模型未报 onset 就等同于确定没有 onset。

- **[W6] VocalParse 官方仓库与论文摘要**：`https://github.com/pymaster17/VocalParse`；`https://arxiv.org/abs/2605.04613`。2026 年 5 月发布的联合歌词／音符结构化转写路线。
- **[W7] VocalParse 官方模型卡**：`https://huggingface.co/pymaster/VocalParse`。重点核查 Limitations：主要普通话训练，不预测真实音符时长，长于 30 秒的输入需要预切分。
- **[W8] Spotify Basic Pitch 官方仓库**：`https://github.com/spotify/basic-pitch`。通用多音高转写与 pitch bend 支持，不能据此推出它是本项目主唱边界的最佳模型。
- **[W9] MIDI Association：Standard MIDI Files**：`https://midi.org/standard-midi-files`。SMF 的时间事件与多轨交换用途；本次未读取付费／登录后的完整规范 PDF。
- **[W10] Mido 官方文档：Standard MIDI Files**：`https://mido.github.io/mido/files/midi.html`。tick、delta time、PPQN 及 tempo 的时间关系。此文档是序列化检查参考，不表示本项目使用 Mido。
- **[W11] mir_eval 官方文档：transcription**：`https://mir-eval.readthedocs.io/latest/api/transcription.html`。一对一音符匹配与起音、音高、结束时间容差。

## 最终建议

**先修“歌词在什么时间”，再修“什么才算一个音”，最后比较“哪个模型更适合”。** 本次证据支持优先解决长音频对齐退化、合理长音候选缺席和最终器开关／语义耦合，而不是先换一个更大的模型或批量删除短音。保留 GAME＋RMVPE，完善现有结构化解码，是当前最有依据、也最容易逐项验证的改进路线。
