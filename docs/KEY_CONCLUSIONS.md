## Architecture conclusions

- Uta! Studio is native-only in Production. No Python service/runtime fallback is part of the product architecture.
- Studio/app-core/desktop remain decoupled from backend implementation crates. Studio communicates with packaged `uta-analyze` / `uta-runtime` machine protocols rather than importing Analysis Engine or Runtime Manager internals.
- Runtime Manager is the source of truth for model identity, acquisition, validation state, runtime/backend compatibility and installed generation.
- `BenchmarkCandidate`, `Experimental` and `Unsupported` are not Production support. Production routing must fail closed when no `ProductionPinned` backend/model generation is available.
- CPU is an explicit reference/diagnostic lane, not an automatic Production fallback.
- Model/runtime installation is explicit user action. Startup, status views and diagnostics must not silently download models.
- Hashes are compatibility metadata, content IDs, fingerprints and provenance, not acceptance/rejection gates. Trust boundaries retain safe-path, regular-file, declared-file-set, byte-size, schema, semantic identity, dependency correlation, completeness and atomic-publication checks.
- Qwen3-ASR-1.7B and Qwen3 Forced Aligner intentionally keep their independent pinned C++/GGML runtimes. They are not OpenVINO migration targets.
- Every current non-Qwen OpenVINO IR route exposes explicit CPU-only diagnostic execution with no automatic CPU fallback. Per user routing direction, all five RoFormer resources—BS-RoFormer, Inst V2, Harmony, Denoise and Dereverb—expose only their full-song-qualified GGML/Vulkan `BenchmarkCandidate` route and must never launch OpenVINO. Their route cannot be changed by a global or per-model OpenVINO override. Each invocation forces batch size 1, no async submission and a serial pipeline. Settings can persist backend choices for other models through `model_backend_overrides`; Qwen retains its independent pinned runtime.
- Non-Qwen Vulkan or Level Zero execution requires explicit user permission before context creation. Qwen-family Vulkan/Level Zero is exempt from that extra repository rule.
- The host's Arc B580/OpenVINO path has a concrete persisted failure signature. An intermediate FireRed implementation that retained Encoder, CTC and all 11 decoder buckets simultaneously reached about 5.22 GiB host HWM, aborted on `CL_OUT_OF_RESOURCES`, and produced an Xe CCS timed-out job plus engine reset. A subsequent current-source short run on that same boot completed but was followed by a hard reboot about 3 minutes 20 seconds later. After reboot, the identical current stage-major short run completed with exact output and remained stable through a 420 s post-exit watch with no kernel GPU fault. This supports poisoned same-boot state as a material factor; later clean-boot Japanese lifecycle and Chinese full-song runs qualified the current stage-major implementation without erasing the historical fault. Linux 7.2 and Compute Runtime 26.31 remain context, not general validation; process-local debug flags and `xe.wedged_mode` are not product defaults.
- Continuous F0 evidence is not the same thing as target-note evidence. RMVPE/FCPE output must not be silently quantized into authoritative MIDI notes.
- Optional experts must not silently replace baseline experts: FireRed does not replace Qwen ASR, FCPE does not replace RMVPE, and Basic Pitch/STARS/ROSVOT do not replace GAME. The STARS/ROSVOT annotation RMVPE (`19dc1809…`) also does not replace ordinary Production RMVPE (`5370e71a…`).
- Correlated evidence must preserve dependency metadata. STARS/ROSVOT conditioned on the shared frontend generation, exact annotation RMVPE, and TimedTranscript/G2P cannot be counted as independent confirmation of those inputs.

## Implemented analysis conclusions

The Analysis Engine has real typed stages for transcript fusion, alignment fusion, singing fusion, candidate graph construction and VocalChart finalization. Unknown evidence must remain unknown rather than being fabricated.

Current source contains strict schema-2 consumers for Qwen transcript and alignment evidence. Qwen ASR now uses deterministic contiguous `qwen-asr-windowed-90s-v1` long-input execution, records every window's complete audio coverage and runtime-detected language, and chooses aggregate language only from that evidence. The Qwen Forced Aligner retains deterministic `qwen-align-windowed-v1` behavior. Both are integration-ready and remain `production_ready=no` pending broader labeled full-input singing quality/stability acceptance.

`melband_roformer_denoise_aufr33` native integration is accepted on its only advertised route: exact stereo DSP, packaged GGML/Vulkan worker protocol, dry-stem semantics, cancellation/recovery, Runtime Manager LocalImport/validation/Benchmark resolution and the real Analysis Engine process route pass. OpenVINO routing is rejected. It is `integration_ready=yes`, `production_ready=no` because the backend remains `BenchmarkCandidate`; broader Production validation remains open.

## RoFormer safety conclusions

- All five RoFormer resources now pin the user-selected GGML/Vulkan `BenchmarkCandidate` route and must never launch OpenVINO. A supervised `uta-ggml-worker` executes the exact five legacy GGUF paths using the pinned in-repository C++ graph and GGML/Vulkan runtime recipe. It validates safe paths, regular files, declared file sets, expected sizes and runtime/model semantic contracts while retaining hashes only as provenance metadata; it emits typed lossless stem protocols, never falls back to CPU, and always invokes the native engine with `--batch-size 1`, `--vulkan-no-async` and `--serial-pipeline`. The durable default GGUF root is `<runtime-store>/ggml-models` (normally `~/.local/share/uta-studio/runtime/ggml-models`); `UTA_STUDIO_GGML_MODELS_DIR` remains an explicit override. All five catalog-selected GGUF resources resolve there without `/tmp`, and every GGUF completed an isolated 305.813333 s full-song run: BS GuideVocals 287.050 s, Denoise 152.887 s, Dereverb 81.580 s, Inst V2 174.533 s and Harmony 151.525 s. Every output was decodable, non-silent, exact-duration stereo 44.1 kHz FLAC; source hashes remained unchanged, workers exited cleanly and no matching kernel GPU fault/reset appeared. Harmony lead+residual reconstructs all-vocals to -94.73 dB RMS error. These graph-specific successes do not authorize repeat/stress/concurrent runs.
- Task 14 is `READY`. Bubble A verified/resolved all 14 resources and proved forced OpenVINO fails for every RoFormer. Bubble B ran all five RoFormer resources serially through GGML and produced exact 6 s Guide, Lead, Clean, Dereverbed and Instrumental FLACs; only RMVPE/FCPE evidence used OpenVINO. Bubble C preserved caller-canonical Chinese lyrics and emitted a valid Candidate chart with 36 ordered non-overlapping notes, 1,209 separate continuous-pitch points, STARS=40 and ROSVOT=35 correlated candidates, and no degradation. Bubble D produced FireRed `你好世界` three times, 601 finite/nullable FCPE frames and 516 finite Basic Pitch frames. Bubble E observed active GGML and OpenVINO children, received typed cancellation with no partial output, then recovered each backend on a 6 s smoke. Boot/source identity remained unchanged, no Worker remained and no matching kernel GPU fault/reset appeared. The earlier stale OpenVINO Denoise hard reboot remains historical safety evidence rather than current route qualification.
- Do not repeat a lifecycle that co-resides full PyTorch state, exported graph data and ORT/OpenVINO sessions after an OOM or runaway-memory result.
- Heavy conversion/reference phases must be separated into processes, use disk-backed intermediates where appropriate, and reserve at least 8 GiB for the OS/compositor.
- A generated ONNX/IR file is not semantic support. Stereo/timeline preservation, actual target-stem semantics, repeatability, cancellation, Runtime Manager state and the real Engine process route are required.
- BS-RoFormer and MelBand-RoFormer have different band gathering and DSP contracts, but the accepted EP317 and Inst V2 checkpoints share the same high-level axial topology: BandSplit, 12 full-context time/frequency Transformer pairs, normalization and per-band Mask MLPs. Reuse the bounded island/microbatch/rolling-residency pattern only after exact model-specific topology and parity checks; never assume their DSP layouts are interchangeable.
- Oversized MelBand-style graphs must preserve configured attention context by splitting into manifest-pinned IR islands. Microbatch only independent batch axes, use explicit CPU/GPU placement rather than fallback, and use rolling GPU residency when aggregate compiled buffers exceed the device envelope. Do not shorten `T` as a memory workaround. For multi-chunk audio, schedule stage-major: prepare chunk tensors on the host, compile one GPU island, run it over all chunks, then release it. Per-chunk recompilation of every island can destabilize the host even when each island is individually bounded.

## Product/legal conclusions

Technical integration readiness and release/distribution notes remain distinct, but the repository's Production license gate is intentionally permissive: an exact model/checkpoint that is publicly available under an explicit open-source/open-model license passes the license portion of technical Production. Attribution, share-alike, non-commercial, commercial-use, or redistribution conditions remain recorded and user-visible but do not by themselves force `production_ready=no`. Missing, ambiguous, or non-open license identity may still block Production. Licensing must never be used to hide an unfinished worker, parser, route, protocol, packaging path, or semantic/quality gate.
