# Uta! Studio internationalization guide

Uta! Studio’s native Bevy interface supports English (`en`), Simplified Chinese (`zh-CN`), and Japanese (`ja`). English is the source language and the guaranteed fallback.

## Design goals

- No network access is required to render translated UI.
- No new runtime dependency is introduced.
- Existing English UI remains valid when a key is missing.
- The selected language is persisted in `AppConfig`.
- The application can follow locale information supplied by its launch environment.
- Translation changes remain reviewable as normal JSON diffs.

## Files

```text
desktop/src/studio/i18n.rs
desktop/assets/i18n/en.json
desktop/assets/i18n/zh-CN.json
desktop/assets/i18n/ja.json
```

The catalogs are embedded with `include_str!`, parsed once with `serde_json`, and retained in `OnceLock<HashMap<...>>` values.

## Locale selection

The effective locale is resolved in this order:

1. `UTA_STUDIO_LOCALE` environment override.
2. The persisted `AppConfig.ui_language` value.
3. `LC_ALL`.
4. `LC_MESSAGES`.
5. `LANGUAGE`.
6. `LANG`.
7. On Windows, the native user locale returned by `GetUserDefaultLocaleName`.
8. English fallback.

Accepted aliases include common underscore and encoding forms such as `en_US.UTF-8`, `zh_CN.UTF-8`, and `ja_JP`. All `zh` locale variants currently use the Simplified Chinese catalog.

In the UI, **System default** is represented by `ui_language: null`. Explicit values are `en`, `zh-CN`, and `ja`. Invalid persisted values are normalized back to system default while loading configuration.

## Catalog convention

Legacy static copy uses the English source string as the JSON key. The English catalog maps those keys to themselves:

```json
{
  "Settings": "Settings"
}
```

The equivalent Chinese and Japanese entries are:

```json
{
  "Settings": "设置"
}
```

```json
{
  "Settings": "設定"
}
```

New dynamic copy uses stable IDs through the typed `UiMessage` API:

```json
{
  "message.path_opened": "Opened {path}"
}
```

`localized_message` resolves the ID and its named parameters before the Bevy
`Text` entity is created. This prevents an English punctuation change from
breaking parameterized Chinese or Japanese copy. Missing entries use the
typed English fallback. Source-string keys remain supported while existing
static call sites are migrated.

## Runtime behavior

`localize_ui_text` runs after a scoped UI rebuild and processes newly added or changed, non-editable Bevy `Text` components. Legacy static strings use exact catalog lookup. Stable-ID messages are localized at construction time; there is no prefix/suffix scanner for dynamic English text. User-selected paths and other parameters are passed explicitly and preserved verbatim.

Editable fields are excluded so the application never translates lyrics, metadata, paths, search queries, or other user input.

Because the first migration uses English source strings as keys, a non-editable user-supplied display value that exactly equals a catalog key could theoretically be translated. This is uncommon and display-only. The recommended long-term migration is to attach explicit message IDs or a `LocalizableText` component at construction time.

## Adding or changing a translation

1. Add the same English key to all three catalog files.
2. Keep placeholders unchanged, including braces such as `{value}`.
3. Do not translate product names, model names, paths, file extensions, or keyboard keys unless the surrounding language requires an explanatory label.
4. Keep button labels short enough for the existing layout.
5. Run the catalog parity test.
6. Review the result at 80%, 100%, and 140% font scale.
7. Test long Chinese and Japanese strings in narrow windows and confirmation dialogs.

The catalogs must always have identical key sets and non-empty values.

Documentation Center article text is not looked up in these catalogs. The viewer selects `docs/user-guide/en.md`, `zh-CN.md`, or `ja.md` first, then renders that source. Viewer chrome still uses this catalogue.

## Dynamic templates

Dynamic messages use named placeholders in catalog keys, for example:

```json
{
  "message.app_version": "版本 {version}",
  "message.diagnostics_summary": "{passed} 项通过 · {failed} 项失败 · {skipped} 项跳过 · {apis} 个 API"
}
```

When adding another dynamic message:

1. Add a stable `message.*` key and every translation to the catalogs.
2. Add a typed `UiMessage` variant with an English fallback.
3. Render it with `localized_message` at the point where UI state or `Text` is created.
4. Preserve user values verbatim and keep placeholder names identical.
5. Add a unit test for at least one non-English locale.

Avoid broad substring replacement. It is difficult to review and may alter song titles, paths, or diagnostic details.

## Translator guidance

### English

English is the source and fallback. Keep copy direct and action-oriented. Use sentence case for buttons and headings unless an existing visual section intentionally uses uppercase.

### Simplified Chinese

Use concise Mainland Simplified Chinese UI terminology. Preserve established technical names such as WhisperX, Demucs, CUDA, OpenVINO, UTZ, and UltraStar. Prefer “谱面” for chart, “分轨” for generated stems, “对齐” for alignment, and “运行环境” for runtime.

### Japanese

Use concise Japanese product UI terminology. Preserve model and format names. Prefer “譜面” for chart, “ステム” for stems, “アラインメント” for alignment, and “ランタイム” for runtime. Avoid translating a destructive action into wording that understates its effect.

## Validation commands

From the repository root:

```sh
cargo fmt --check
cargo test -p uta-studio-desktop i18n
cargo check --workspace
```

For the repository’s canonical packaged build:

```sh
nix build path:.#uta-studio
```

Recommended manual smoke test:

1. Launch in English and open Library, Folders, Settings, a song, and the editor.
2. Switch to Simplified Chinese; confirm the current page rebuilds immediately.
3. Restart and confirm the selection persists.
4. Repeat for Japanese.
5. Select System default and launch with `LANG=zh_CN.UTF-8`, then `LANG=ja_JP.UTF-8`.
6. Confirm lyrics, song titles, file paths, and editable metadata are not translated.
7. Trigger setup, cache-clear, folder-removal, and unsaved-editor confirmation dialogs.
8. Check long notices and diagnostic summaries for clipping.

## Continuing migration

Replace remaining source-string lookup incrementally with stable message IDs:

```text
settings.general.interface_language.label
settings.general.interface_language.description
```

This approach improves translator context, supports future plural rules, and prevents collisions with user-visible values. Do not remove the source-string path until its callers have all moved to typed IDs.
